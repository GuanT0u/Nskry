# 输入体验改动与架构边界复审

日期：2026-10-12。未提交/推送，未安装用户插件，未停止用户程序。

## 范围与结论

核对二次规划、Core/插件契约、插件开发标准和输入扩展规范；检查本轮输入改动的
Settings → 快捷键注册 → 框选 → Core 编辑器/插件调用链，以及 Registry/Runtime、
共享编辑、监控可见性和视觉层的边界。重点审查上轮未提交的体验改动。
不是全仓库逐行安全审计，也没有重新评估 OCR 模型准确率或重写采集引擎。

主体结构符合规划：共享编辑归 Core，OCR/滚动采集仍为可选插件，metadata 不加载 DLL，
设置按需创建、关闭释放，插件资源不因新增设置项而预热。发现的局部偏差已纠正。

## 已修复：严重性与必要性

| 优先级 | 必要性 | 原问题 | 修复与边界 |
| --- | --- | --- | --- |
| P1 | 未来配置兼容必须 | Save 重写预留 capture/updates 字段，并丢掉未知根/嵌套字段 | 按需读取旧 JSON，仅覆盖已实现字段；递归保留未知对象、数组和保留值。不常驻第二份 JSON 树；原文件损坏/不可读则拒绝覆盖 |
| P2 | 插件来源规范必须 | AllShortcuts 按 OCR/Scroll ID 强制 official 分区 | 已安装包一律沿用 Registry 来源。只有未提供功能时的产品 launch 预留项进入预留官方区；不是签名认证 |
| P2 | 配置可靠性必须 | 已加载插件 configure 抛异常被吞掉；关闭通知后也可能无提示 | Runtime 返回失败 ID；Settings 的 Apply 成功可携带警告，直接显示于设置结果，不受通知开关影响。v1 void 导出仍不能检测静默不执行的 DLL |
| P2 | 故障提示必须 | 持久化/启动设置失败时，快捷键回滚失败信息被覆盖，仍声称全部恢复 | 区分内存恢复、系统绑定恢复及 Windows 启动项恢复，保留具体失败信息 |
| P2 | 扩展列表必须 | 控件 ID 根据行号增长，第 5000 行后越过原路由范围，继续增长会产生 16-bit 别名 | 控件保留固定动作 ID，从发送控件读取完整行索引，验证父窗口及对应行控件；补 5002 行目录回归 |
| P2 | 基础行为必须 | Rebind 走另一套先注册后注销逻辑；相同键重新绑定可能失败，批量绑定重复 command ID 未预检 | 保留接口但复用统一事务，预检空/重复 ID，错误前不注销旧绑定；补同键 rebind 测试 |
| P2 | 可见体验必须 | 跳转提示只 invalidate 父窗口，WS_CLIPCHILDREN 下未确保文字控件重绘；Load 未恢复隐藏显示控件 | 单独刷新目标 label，重载恢复显示模式，保留短时定时器与离屏行虚拟化 |
| P2 | 图像预览必须 | 网格 Graphics clip 未恢复，可能裁掉下/右切线 | Save/Restore 局部 Graphics 状态，切线遵循线型；不修改输出像素 |
| P3 | 架构纠偏需要 | 通用按钮转发通过窗口类名包含 Crop 猜编辑上下文 | 显式 ButtonKeyContext 参数，窗口改名不改变快捷键行为 |
| P3 | 单一元数据来源需要 | Core 重复维护 OCR 局部键目录，并可能把全局 launch 下发 DLL | 删除局部 fallback 表；旧包仅生成通用 toolbar launch。DLL 配置只含自己的局部绑定，并检查命名空间 |
| P3 | 高频资源优化需要 | PluginMatches 每次轮事件重新建解析流；配置 provider 每行复制全部 UserSettings | 按文本/kind 缓存编译组合；provider 直接取有效值，空值禁用仍有效 |
| P3 | 可维护性需要 | 过时控件常量/GetText、重复默认值和密集单行逻辑 | 删除无调用私有项与重复默认赋值；整理小模块格式，不整份重排 main/OCR/采集窗口 |
| P3 | 防御性需要 | 自定义光标 helper 默认调用者永远传有效索引 | 越界回退系统指针；合法调用保持原样 |

JSON 序列化增加深度限制、非有限数拒绝及不依赖 locale 的数字输出。
读取旧配置是在保存操作期间，不是启动联网、轮询或额外常驻服务。
原子替换仍使用临时文件、flush 与 rename；这不宣称多进程配置合并、断电硬实时或 Registry/pending 事务已全部完成。

## 必须保留 / 非必须 / 不应删除

- 必须：输入解析/冲突验证、录制中暂停与恢复注册、失败回滚、DLL-local namespace/所有权检查、
  页面销毁与虚拟行、原图/导出像素分离、位图回调所有权、测试与识别 trace。
- 已删除/合并：宿主重复 OCR 局部快捷键表、旧输入控件私有常量/读文本 helper、
  重复默认赋值、Rebind 的第二套注册路径、窗口类名行为猜测。
- 可选但有明确用户需求：General 跳转、闪烁提示、自定义光标、Cut 网格/旧样式、预设。
  不是正确运行的最低要求，但不能以“非必须”为由移除已承诺体验。
- 必须保留的未来契约：API 2 structSize/version/reserved、standalone 位、按需/startup策略、
  staging/rollback、未知配置与命令 ID、独立版本输入扩展。未使用不等于死代码。
- 不实施的大重构：共享 Image Editor 历史 private 类名、主入口/原生窗口文件拆分、
  公共服务接口升级。先保持行为测试，再逐模块迁移；不为了改名引入额外插件前置。

## 偏轨倾向与后续门禁

1. main.cpp/部分 UI 窗口仍较大：继续添加路由时抽纯策略或已有 service，
   不把图像算法、插件配置解析或产品特判继续塞入主入口。此次仅抽可测占位目录辅助方法。
2. 进程内插件仍非沙箱：C++ catch 不能安全恢复访问违例、恶意线程或错误 shutdown。
   重资源 OCR 使用既有按需 worker，不能以“捕获异常”替代隔离/认证。
3. void configure v1 没有确认协议：此次可报告抛出异常，不证明插件内部采用了配置。
   若以后需要强确认/跨插件服务，新增版本契约，不占 API 2 reserved、不私读宿主设置。
4. 官方身份仍非密码学认证：Registry 是来源记录；签名、官网 catalog 认证/撤销仍是发布门禁，
   不按 ID/作者文字提升官方信任。
5. 更新 service 仍同步，慢网络可能阻塞设置；下一阶段应单独设计取消、UI dispatch、
   快照所有权和任务回收，不在本轮临时加常驻 worker。
6. 当前快捷键按精确 VK 修饰键、单主键匹配。IME/AltGr/系统保留键仍需实机测试；
   全局 Win32 numeric ID 随事务增长，极大量重绑的范围管理可单独补强，不能将系统注册无限 ID 当作保证。
7. 配置保留按当前 JSON 的 double 数字模型进行语义往返，不保证原文本排版或超出 double 精度的大整数词法完全不变。
   Settings 单实例保存，不提供多进程并发写的字段级锁/事务。

本轮补充了插件开发标准的 Core/输入实现约束与输入导出的线程/失败边界。
不修改 GPL/插件例外，不增加在线请求、模型预热或后台输入 hook。
