## 对当前漏字现象的解释

当前管线确实会尝试多种图像处理方式，并把不同轮次的识别框合并，但它无法保证每轮识别都找回同一批文字。质量分数是行级启发式判断，主要发现空结果、低行高、低覆盖率或疑似中文字间隙；个别汉字被漏掉或识别成另一个有效字符时，评分可能仍然认为这一行质量足够。

因此，“每次重试漏掉的字不一样”说明现有 OCR 输出及其启发式补救存在不稳定性，并不单凭这一现象就能证明某一项预处理完全没有生效。要量化实际提升，还需要用固定截图集做对照评测；本次仅做代码阅读，没有运行构建或测试。

## 建议后续跟进

1. 实现可在线程/任务间传递的取消机制，并明确 Windows OCR 正在运行时的取消边界；代次检查可继续用于丢弃过期结果。
2. 修复取消或过期返回时原始 `HBITMAP` 的所有权和释放路径，避免后台识别被新请求替换时泄漏。
3. 使用固定的中英文 UI 截图评测集记录各轮识别差异，检验评分、缩放、增强与二值化是否真正找回漏字；仅凭当前启发式分数无法判断逐字准确率。
4. 更新方案文档的第 14 节勾选状态，使其与实际实现保持一致。
