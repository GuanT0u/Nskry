## 1. 功能与入口

### 区段切除、拼合

- 归属 Core 通用 Image Editor，不依赖 Scroll/OCR 插件。截图工具栏“编辑”、固定图右键
  `Crop / cut strips (static image)`、监控右键 `Crop / cut strips (current frame)`、OCR Edit 均可进入。
- `Cut rows` 删除整行区段，`Cut columns` 删除整列区段：拖出两条切线，可再拖切线调整，
  `Delete strip` 确认；`Cancel cut`/Esc 退出当前模式；独立 `Undo cut`/`Redo cut` 操作历史。
- Copy/Save 直接输出当前裁剪范围内**已确认**的拼合内容。未确认切线不会进入输出。
  标注编辑仍通过 `Open annotation editor` 进入，固定图片是显式选择，不强制固定。
- 原图只有一份，历史保存区段元数据；预览只绘制可见区段，后备缓冲按视口缓存。
  放大镜取样实际拼合邻域，OCR ROI 使用拼合后的像素；合成图不伪造实时来源 HWND。
- 上限：256 个切除历史、128 个矩形映射片段、单次物化输出 512 MiB；超过上限拒绝，
  不能删成空图。不是矩形挖空/填补，也不是矢量标注或任意局部变形。

### 监控源聚焦时隐藏

- Settings / General 的 source-focus auto-hide 开关保存全局默认，默认关闭。
  PiP 右键选择跟随全局、本窗启用、本窗禁用；本窗覆盖不写成所有窗口的默认。
- 正常路径使用 UI 线程 WinEvent，不做周期焦点扫描；菜单/编辑交互期间保护窗口。
  隐藏后取帧但跳过 GPU 裁剪及 PiP 缓存/Present；稳定隐藏 1000 ms 后销毁采集会话。
- 回到其它窗口时不抢焦点地显示并重建采集；等待新帧有状态提示，重建失败明确提示重开。
  用户手动最小化后不自动恢复；最小化也暂停图像处理。
- 关闭源窗口及关闭/重建监控的通知带生命周期保护，旧监控的消息不能关闭新监控。
  源窗口关闭回调不在 WGC 回调内部同步 Stop，避免等待自身退出。
- 焦点 hook 失败时才降级为 250 ms 轮询；不能追踪源销毁则不硬回收，提示事件支持受限。
  降级不等于零唤醒。软暂停允许已在途处理完成，不能声称瞬时绝对零帧。

### 阴影与圆角

- Settings 新增 `Window effects` 页；两个开关独立、初始关闭。Apply 更新已有及后续 Pin/PiP。
- 阴影：Win11 预设 18%/4 DIP blur/12 DIP range/2 DIP offset；近似 macOS
  22%/6/18/3。Custom 继承上一预设，可调不透明度、模糊、范围、偏移。
- 圆角：Win11 原生偏好；macOS 近似固定 10 DIP；自定义固定 DIP 或短边百分比。
  DIP 按窗口 DPI 换算，百分比按物理短边算。系统偏好转自定义使用标明的 8 DIP 参考值，
  不假装它是读出的系统真实半径。
- 阴影是 8 个外缘小型 layered 工具窗与几何 alpha 缓存；只在尺寸/DPI/参数变化时生成，
  移动/隐藏复用。缩放交互暂隐藏阴影、结束后再生成；不读取实时帧、不做每帧 blur。
- 所有窗口的自有阴影 DIB 总预算 32 MiB；关闭/禁用释放表面和 HWND。不是 LRU 全局缓存，
  系统/DWM 另有开销，不能把本预算说成软件或 GPU 总内存上限。
- 原生圆角 API 不可用时 region 降级；自定义用 region。效果只作用显示，Copy/Save/OCR 不烘焙。
  阴影生成失败保持内容窗口可用；位置批量更新失败隐藏辅助窗，避免残留错位阴影。

## 2. 结构与未来兼容

- 纯逻辑：`image_edit_model.*`、`monitor_visibility_policy.h`、`window_visual_settings.h`。
- 系统适配：`monitor_visibility_controller.*`；显示适配：`window_visual_style.*`。
- main 负责绑定生命周期与设置，Pin/PiP 共享同一套效果实现；不加入插件私有互调。
- API 2 布局/reserved 字段及 installed != loaded 原则保持不变；仅澄清合成图上下文语义。
  未来第三方编辑工具/样式贡献仍需版本化协议，此实现不暗建公共 C++ ABI。
- 采集适配同时修复源尺寸改变后帧池重建、裁剪尺寸限界、PiP 小帧读回越界及重绘旧区域残影。
- 采集委托通过共享回调门禁取得 owner 使用权，Stop 先阻止后续进入、等待在途回调后再回收。
  延迟排队的回调不再持裸 `this`；计数和条件等待使用同一把锁，避免丢失唤醒。
  Stop/析构必须从采集回调外请求，当前宿主通过 UI 消息满足此约束。

## 3. 验证记录

- Release 构建：`build/verify` 成功。
- 原有和首批新增 13 项 CTest 全通过（最近一次 8.62 秒）。
- 新纯逻辑测试：两个方向、反向切线、交叉切除、每个输出像素、裁剪映射、单像素余量、
  无效输入、历史/片段上限事务拒绝、撤销分支、2000×20000 元数据编辑 20 次及恢复。
- 宿主 UI 测试：实际 GDI 拼合输出逐像素核对、模式取消、无插件编辑器、设置保存/读取、
  Settings 控件布局、焦点/交互保护/覆盖/硬回收/恢复决策、源销毁只报告一次。
- 30 次独立窗口视觉生命周期：开/关/移动/隐藏/缩放/关闭后 GDI 与 USER 计数不持续增长；
  移动/隐藏不重新生成像素，交互缩放结束生成一次。测试均使用测试自有窗口，不操控其它应用。
- 一次独立测量：240×160、30 个串行样本，生成阴影 p50 7.072 ms、p95 7.6298 ms。
  这仅是当前机器小窗 CPU/系统调用墙钟时间，不是低配保证、DWM/GPU 成本或 30 并发窗数据。
  环境：Windows build 26200、16 个可用逻辑处理器；CIM 查询不可用，未完整记录 CPU 型号/
  RAM/GPU/电源状态，故不划为“低配已达标”。
- 增加 `NskryMonitorFrameTests`：实际 D3D 32×24 小帧读回到 80×60 请求画布，
  逐像素核对内容及空白余量；隐藏窗口不缓存新帧，按原尺寸重绘不越界。测试通过，
  最新一轮 `build/verify` 14 项 CTest 全通过（12.39 秒，期间另一路构建并发）。
- 回调门禁纯逻辑回归：Stop 等待在途租约，Stop 后排队委托不碰 owner，异常也释放租约。
- 门禁修复后的最终 Release 构建：`build` 和 `build/verify` 均成功；两套各 14 项 CTest
  全通过，分别 11.54 秒与 8.95 秒（两套任务有部分并发，不作为性能基准）。
  `git diff --check` 通过。实际 WGC 端到端仍属于下节待验收项。
- 可交付程序：`build/Nskry.exe`；独立验证程序位于
  `build/verify/Nskry.exe`。构建没有启动用户实例或更新 AppData 插件 Registry。
- 依赖配置仍有 OpenCV 对较新 MSVC 版本的识别提示与 CMake policy/deprecation 提示，
  本次构建没有因此失败；本轮没有为压制提示修改固定第三方依赖或降级工具链。

## 4. 未完成的实机验收与限制

1. 真实 WGC 源聚焦切换、隐藏后回收、恢复首帧 p95、源关闭/缩小、多次 Alt-Tab：
   自动状态/像素测试不能代替这套端到端性能验收。
2. 1/10/30 个同时固定窗、跨屏 100/150/200% DPI、休眠/RDP、低资源机器/电池模式；
   稳态 60 秒 CPU/Private Bytes/GPU engine 与 DWM 增量尚未测量。
3. 系统接受 DWM 圆角偏好并不保证无标题栏窗口实际呈现圆角；自定义 region 边缘可能阶梯。
   阴影外缘片不覆盖矩形内部被圆角裁去的角落；视觉质量及跨进程输入穿透/z-order 需手测。
4. 尚未做 B 路线与 DComp 的同场 A/B 原型比较，因此只是先尝试推荐路线，不能宣称普适最省资源。
5. 本轮三个能力都是 Core 改动，不需要安装新插件包；既有包构建产物不等于安装到了用户 Registry。

如实机门禁不通过，按总案调整回收延迟/视觉实现，不通过加持续轮询、整帧读回或删未来接口掩盖。
