# 长截图向上滚动拼接（0.5.2）

日期：2026-10-30。

## 问题与实现

旧算法只寻找正位移，成功后总向长图底部追加；无法处理向上滚动，也没有当前视口在整张长图中的位置。

- 将原有帧验证、差异、匹配算法抽为插件私有 `scroll_stitch.h`，便于独立回归，不改变 SDK/API 2。
- 使用正反两次匹配确定有符号位移，反向通过交换输入实现，不复制/翻转整张帧。
- 两方向均有候选时比较误差，分不清则拒绝；保留原重叠范围、纹理及重复模式置信检查。
- 记录视口在长图中的位置，向上超过顶部时补入顶部新行，向下超过底部时追加新行。
- 在已有范围内来回滚动只更新视口位置和参考帧，不重复插入像素；顶部扩展后同步重定位坐标。
- 采样仍在滚动过程中及停稳时进行。自动滚动按钮仍向下滚动，本轮新增的是手动双向采集。
- 保留 192 MiB 输出与 512 MiB 工作内存安全预算。顶部插入使用现有 vector，需搬移已有像素；
  长图接近上限时的延迟未测量，不宣称双向匹配/顶部扩展零成本或性能提升。
- 插件 manifest 与 DLL 版本同步为 0.5.2；网站仅同步版本数据，不修改进行中的前端样式。

## 验证

- `build/verify-translation` Release 完整构建通过，生成 `installer/bundled/nskry-scroll.nskryplugin`。
- 新增 `NskryScrollStitchTests`：确定性合成文档的上下切换、顶部/底部新区域、反复经过已有区域，
  每一步比较输出尺寸及全部像素与原文档精确区间一致。
- 覆盖静止、无重叠、空白、周期性重复、不相关帧和非法输入，均拒绝误拼。
- 完整 CTest：47/47 通过，91.98 秒；Windows 运行时测试在测试进程/窗口中执行。
- 网站元数据校验通过；`git diff --check` 通过。

尚未实机验收：真实浏览器/触控板连续上下滚动、页面固定头尾、动态加载、动画和超长图顶部插入延迟。
原有纹理少、重复区域或单次移动过大导致拒绝拼接的限制仍存在。
没有安装插件、停止用户程序、提交或 push。用户需手动安装 0.5.2 包并正常退出、重启应用更新。
