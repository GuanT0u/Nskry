# 固定区域录制首帧修复（2026-10-23）

## 根因与证据

修复前 `NskryRecordCaptureTests` 可重复失败：固定桌面区域320×180缩为160×90，首次 `read` 返回 S_OK，但中心 BGRA 为0,0,0,0，绿色像素0/14400。相同范围的 WGC 窗口跟随为50,170,30,255、14400/14400；后续未缩小录制的视频解码与时长通过。

临时首帧元数据诊断捕获到 `LastPresentTime=0`、`AccumulatedFrames=0`、`LastMouseUpdateTime=359033525390`。Desktop Duplication 首次只通知了鼠标更新，还没有桌面图像，原实现却继续读图并发布 S_OK。该问题不在 GIF 调色板、编码时间戳或上轮 ReadTiming 状态读取优化中。诊断输出已从产品代码移除。

## 修复

- `DesktopRegion` 增加实例内的“已有桌面图像”标记；首次真实桌面更新前，鼠标-only 通知保留鼠标位置/形状后返回 S_FALSE。
- 已取得帧仍由原 RAII 守卫 ReleaseFrame，既不泄漏也不占住 duplication 帧；采集调用不阻塞，沿用 RecordSession 的启动等待、10秒超时和取消机制。
- GPU缩小及CPU回退两条成功路径均更新标记。首次有效桌面后仍允许鼠标更新，未改变正常录制的光标行为；暂停重新创建采集实例时重新等待有效桌面。
- 只增加一个布尔状态，无新增帧缓存、线程、定时器或空闲轮询。不改变 API2/采集v1/v2 的结构、所有权、输出范围和DPI语义。

## 测试改进

保留对第一个 S_OK 帧的严格颜色检查，没有通过等待“恰好变绿”或跳过断言来掩盖问题。增加 S_FALSE 等待次数、测试自有图像中心BGRA输出；不记录用户截图。窗口跟随测试使用局部结果，最后再合入总结果，不再把之前的固定区域失败打印成窗口跟随失败。

修复后连续三次真实采集回归通过（8.19/7.74/6.95秒，共22.92秒），固定与跟随均为14400/14400预期绿色像素，三轮停止后的短窗口CPU增量均为0ms。覆盖MP4解码、时长、暂停恢复、窗口移动/尺寸改变/源关闭。测试只操作其自建窗口，不停止用户程序。

最终完整 CTest **32/32通过，55.07秒**，包括截图/监控UI、OCR、插件生命周期及录制相关回归。`git diff --check` 通过。

## 交付与边界

`build/verify` 完整构建通过，常用 `build/Nskry.exe` 已重建。本修复位于宿主采集服务，不是录屏插件DLL；仅安装插件包不能替代Core更新。没有自动安装插件或 push。

低配机器、HDR、多显示器旋转、休眠/设备丢失等未在本轮增加实机验收，不据此扩大通过声明。
