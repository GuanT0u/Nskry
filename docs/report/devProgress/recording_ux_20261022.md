# 录屏 0.4.0 体验改进（2026-10-22）

## 完成范围

1. GIF 移除 RGB332 固定调色板。≤256种颜色时使用固定容量哈希表构建精确逐帧调色板；超过时使用 WIC 自适应调色板，分析采样不超过256×256，不缓存整段动画。修正实测发现的WIC中性灰索引偏移。格式仍为10fps、960/540上限、每帧256色，复杂照片仍会量化。
2. 固定屏幕选区 v2 使用适配器匹配的 Desktop Duplication，避免建立显示器WGC会话所产生的全屏黄框。选区 staging 读回，不开放共享 immediate context；旋转坐标及独立光标形状在会话内处理。窗口跟随仍为窗口WGC，旧v1保持原行为，不关闭系统安全提示、不做静默后端回退。
3. Trim 增加首尾手柄时间轴，与秒数输入双向同步。按住手柄时显示对应画面，保留原有 Apply/Cancel；预览失败不破坏原文件或阻止数值裁剪。
4. 录前立即显示实际选区红框，不启动采集/编码。选项改为水平工具条，优先选区下方，其次上方，全屏时放入屏内。红框及工具条保持 capture exclusion。

## 资源与生命周期

- 预览仅在拖动时创建一个低优先级协调线程及受原有Job限制的私有worker。最多8次/秒、单个最新待处理时间点，最多640×360 BGRA；没有播放线程、整段帧缓存或闲置解码器。
- 松手排空最后一个请求后关闭worker和线程；快速再次拖动合并到最新请求。关闭、丢弃、导出与预览竞争时先取消并异步等待回收，再处理文件/UI，避免主线程同步等待解码。应用退出取消后排空，随后释放DLL。
- 每次预览寻帧按需打开/关闭解码器，可能受到长GOP、磁盘和GIF顺序解码影响，8fps为请求频率上限，不保证每秒实际呈现8帧。长GIF靠近末尾的预览延迟仍需实机观察。
- 固定区域没有额外采集线程/无限队列；消费者沿用录屏帧调度和背压。捕获输出/设备失效明确停止并由原会话尝试收尾。
- 没有此次完整CPU/RAM峰值测量，也未验证低配机，不用自动测试耗时替代资源测量。

## 兼容边界

API 2结构、reserved、公开采集v2结构不变。私有编码IPC从2升为3，插件包0.4.0必须携带同轮worker；Core也必须同轮更新才能使用固定选区的新后端。不增加跨插件依赖或常驻管理器。未自动安装插件、未停止用户程序、未提交或push。

Desktop Duplication不可用（部分远程桌面/驱动/会话限制）时明确失败。物理旋转屏、HDR颜色、多适配器、显示器拔插、不同DPI、锁屏/休眠、超小工作区、低资源机器仍需实机验收；不能据开发机测试声称全平台通过。

## 验证

- 独立 `build/verify` 完整构建；安装包输出 `installer/bundled/nskry-record.nskryplugin`。
- 新增颜色块及>256色渐变场景，前者最大通道误差0，后者验证灰阶；GIF两帧局部调色板均正确解码。
- MP4/GIF预览请求合并、场景帧正确性、取消、源文件大小不变、结束回收；输出仍能解码并保留正确时长。
- 时间轴坐标/边界、工具条全屏/底部布局、旋转映射有界且一一对应的纯逻辑回归。
- 原录屏控制回归补充手柄拖动、缓存预览及任务回收、录前可见红框和无标题横条位置检查。
- 固定选区真实采集/编码改用v2，解码验证控制UI无泄漏；原窗口跟随移动、暂停后移动、调整尺寸与关闭回归保留。
- 最终完整CTest **30/30通过，39.03秒**；其中Feature 2.37秒、Capture 5.95秒、Control 5.50秒。采集结果解码38帧，控制UI泄漏像素为0。GIF颜色块最大通道误差0；>256色渐变场景的被测灰阶最大通道误差6（不是整个渐变图的全像素误差）。
- 插件包版本0.4.0，包内DLL及worker的SHA-256分别与本轮staging产物一致；`git diff --check`通过，只有仓库既有CRLF归一化提示。
- 测试使用自身窗口及合成内容，不采集用户的真实工作内容。环境拒绝CIM硬件信息读取，未把未知硬件规格包装成低配实测。

## 实现依据

Desktop Duplication的旋转及独立光标元数据约束依据 [Microsoft文档](https://learn.microsoft.com/en-us/windows/desktop/direct3ddxgi/desktop-dup-api)；自适应调色板使用 [WIC InitializeFromBitmap](https://learn.microsoft.com/en-us/windows/win32/api/wincodec/nf-wincodec-iwicpalette-initializefrombitmap)。本轮未请求关闭WGC系统边框的特殊权限。

## 后续代码复审修正（2026-10-22）

- 修剪模式在导出期间统一切换到非编辑布局，范围控件同时禁用指针输入；避免导出尚在读取源文件时又启动一条预览解码请求。关闭窗口时清理待执行的关闭/丢弃/导出意图，避免销毁后回调继续驱动操作。
- 预览结果和完成状态在同一把锁内读取，修复“已读走最后一帧、尚未来得及观察 Done”造成的丢帧/卡住竞态；相同时间点请求合并。预览 worker 在一次拖动手势中复用同一个私有 WIC/MF 解码器，仍只缓存单张低分辨率结果，手势结束后关闭 worker、解码器和线程；没有常驻解码资源。旧的每次请求重开文件/解码器路径已移除。
- 会话快照记录实际传给编码器的目标码率；修剪重编码沿用它，不再落回自动码率。默认码率夹限公式成为纯逻辑函数并有边界测试。注意：系统 H.264 encoder 对静态测试画面的实际平均码率会低于目标值，因此不以媒体实际平均码率等同编码目标；输出时长、帧率和可解码性仍由集成测试核对。
- 录制前选项条在窄工作区改为紧凑宽度，极窄时继续按比例压缩控件，按钮下拉仍显示完整选项；纯逻辑测试覆盖常见窄宽度。移除一个会被随即覆盖的重复状态文本更新。
- GIF 时间累计测试容许一个 100ms 帧粒度，避免系统调度造成的单帧量化抖动被误判为输出错误。
