# OCR 能力拆分与验收（2026-11-27）

## Phase 0–4

Phase 0 审查了 Core、API 2、元数据注册、按需加载、包安装与重启事务。旧文字提取 DLL
持有 Windows OCR 多轮识别、PP-OCRv4 调用、段落拼合和窗口交互。0.3.4 RC2 翻译默认从自己的
`ocr/` 启动同一原生模型，旧纯文本联动可另行勾选。原 SDK 只返回文本，无法给文字提取结果页恢复词框。

Phase 1–2 保留 API 2，新增可选布局 OCR v1。两个功能默认通过宿主取得同一 Provider。
`plugins/nskry-ocr-provider/recognition.cpp` 持有识别逻辑，原有 B/C 处理、自动缩放、候选仲裁、
CTC 数字处理、读序和行高亮继续使用。为控制改动范围，底层 worker、模型源码和共享布局工具
仍位于 `plugins/nskry-ocr/src/`，通过内部 CMake target 构建。文字提取保留结果页、选择、复制、
旋转、重新识别与向翻译交接文字。翻译保留自身配置、文字输入、翻译引擎和在线确认。
删除翻译内重复的识别入口与打包素材。默认精确模式，文字提取可显式切换 Windows OCR 快速模式。
禁用模型的构建显式请求 Windows OCR。

Phase 3 增加独立 Provider 包。Core 为 0.5.1，文字提取为 0.7.0，翻译为 0.4.0。
两功能保留原 ID、快捷键 ID 和设置位置。安装器在选中文字提取时一起装必要依赖。
手动导入需要先安装兼容 Provider，或确认同目录伴随包。下载渠道的已有用户可先手工安装 Provider
再更新。重启操作重新检查依赖，阻止移除仍有消费者的 Provider。功能安装失败后已成功安装的
Provider 可保留供重试。移除最后一个消费者后可手动删除能力包。
纯文本 v1 ID 兼容路径仍可用。新版翻译默认走布局接口，已有纯文本勾选优先查询独立官方 Provider。

Phase 4 在本机隔离用户数据运行实际包、独立 UI、真实离线 OCR 与翻译对照，并同步架构和 SDK 文档。
Core 仅解析元数据与持有调用接口。功能工作线程借用 Provider DLL 引用，任务完成后释放。准确模式每个
请求启动一个受限原生工作进程并等待退出。并发时共享 DLL，官方重任务只接受一个，另一调用收到繁忙，
没有模型常驻或预热。纯文本 v1 的旧宿主路径可保留轻量模块到卸载，模型子进程仍按请求退出。

## 质量与资源对照

同一设备、相同输入、同一个 `NskryTranslationImageAudit`。使用 0.3.4 RC2 归档和 0.4.0
在线候选归档，均使用 `ocr-only`，每张图片两次，首个英文任务为各进程第一次调用。
每轮识别完成后采样子进程退出。并行峰值是同一采样点的父子进程之和。

| 英文首轮 | 3969 → 3781 | 181.23 → 181.20 | 199.88 → 202.50 |

两组输出配对后 UTF-16 内容完全相同。中文公路牌既有的“曼→文”仍能复现。
原文字提取基线的 4 次精确识别输出（普通字、数字、旋转、Explorer）在迁移后日志中
均找到相同、有序的行文本、词元和矩形记录，分别比对 26、25、25、367 条。
各轮均观察到一个 OCR 子进程并退出。首次 OCR 前审计宿主私有提交 2.42 → 2.59 MiB，
最后一次任务完成时 3.04 → 3.34 MiB。这两个数包含测试宿主及翻译窗口，无法代表整机或完整桌面应用。
样本小且进程每轮重启。中文第一轮慢约 0.50 秒，重复轮快约 0.44 秒。工作集约增
1.4–2.6 MiB，私有提交峰值在约 1.5 MiB 内浮动。本轮无法把波动归因到具体子阶段。

## 复核

- `cmake --build build/verify-translation --parallel 8`，另构建 `NskryTranslationImageAudit`。
- `ctest --test-dir build/verify-translation -R "Ocr|Translation|Recognition|CoreTests|UpdateBackend|PluginRuntime|HostPluginUi|GpuReadback" --output-on-failure`。
- 审计参数见 `tests/translation/README.md`。审计样本记录在
  `build/ocr-phase0-4/before.json` 和 `build/ocr-phase0-4/after.json`。
- 历史包用 `NskryUpdateBackendTests.exe --ocr-upgrade <build-dir> <旧包> <新功能包> <Provider包> <功能ID>`
  验证。测试隔离安装目录，对本机已安装插件无影响。
- 本机构建的 `NskryOcrSmokeTests.exe <feature-dll> --workflow --missing-engine` 也通过。设置
  `NSKRY_TEST_OCR_PROVIDER` 指向只复制 DLL、不带模型的临时目录。
- Inno Setup 用本机简体中文语言文件覆盖参数编译成功。干净 Windows 安装验证已按用户要求延后。
- 全量首轮 44/46。OCR 进程失败用例的旧断言后来改为显式的超时状态并通过。该轮的
  `NskryRecordControlTests` 在异常关闭检查失败。最终全量耗时 222.84 秒，`NskryRecordControlTests`
  达到 30 秒超时。该用例直接编译录屏插件，不经过本次更改的宿主能力解析。

第三方能力仍受本机原生插件的信任边界限制。用户选择多个 Provider 的图形界面、
自动下载依赖、跨进程共享模型会话均保留为未来扩展。在线公开发布仍沿用原翻译插件发布流程。
