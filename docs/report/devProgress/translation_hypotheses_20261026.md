# OCR / 翻译三种根因假设的隔离测试（2026-10-26）

本轮是诊断实验，不是修复版本。没有改变识别/翻译决策，没有用标准答案改输出；原图、旧基准、0.3.1 两个翻译包保持不变。未安装插件、停止用户程序、提交或 push。本轮没有调用在线服务，MyMemory 的既有对照只引用上轮记录，不冒充新一次线上验证。

## 1. 结果概要

| 假设 | 实测判断 | 当前信心与边界 |
| --- | --- | --- |
| 简单放大/灰度/增强能修复局部错字 | 6 种处理 × 每种 3 次都未恢复“曼”；原始像素 ROI 加边距也未修复 | 错误位于字形识别端有直接证据；“简单增强就够”的可能性降低，但尚不能完全拆开裁切、归一化与模型能力 |
| 数字分组的空间信号在识别/解码中丢失 | 64 个合成样本数字字符全部正确，但部分间距下分组错误；原图 CTC 仍含间隔时序，最后只有粘连字符串 | 强支持；不是翻译或结果页首次把数字粘起来，也不能将每段 blank 都当空格 |
| 翻译错误主要来自模型语义/领域能力，而非仅 OCR 或 INT8 | 12 个正确原文，INT8/FP32、beam=1/2/4，共 216 次结果；路名及中文字号误译在 FP32 下仍存在 | 强支持存在翻译引擎层问题；量化/搜索会影响措辞，但没有观察到调大参数即可统一修复 |

三种机制可同时存在，不是互斥原因，也不把本次有限样本的结果换算为普适概率。

## 3. 假设一：字形、预处理与几何

### 3.1 固定实际识别裁片

在原生检测、透视校正之后、CTC 解码之前捕获实际裁片和模型输出；正常推理路径本身不变。对四个实际裁片分别测试：原样、2× cubic、灰度、线性对比度、反色、CLAHE。固定对应原推理的 tensor width，每种重复 3 次，共 **72 次识别对照**。

每次仍归一化到模型的 48px 高度。2× 重采样再归一化不是超分辨率，也没有测试一个支持 96px 高度的新模型；不能因此认定所有更高分辨率方案无效。

酒店名结果：

| 处理 | 3 次均得到 |
| --- | --- |
| 原样 | 上海斯格威铂尔文大酒店 |
| 2× cubic | 上海斯格威铂尔文大酒店 |
| 灰度 | 上海斯格威铂尔大酒店（进一步漏字） |
| 对比度 | 上海斯格威铂尔文大酒店 |
| 反色 | 上海斯格威铂尔文大酒店 |
| CLAHE | 上海斯格威铂尔文大酒店 |

另外三个裁片的原有字符识别保持一致；但门牌号的空格问题没有改善。当前孤立的单裁片推理与原批处理结果一致，未观察到该酒店错字由批次组合造成。

### 3.2 原始像素 ROI 的后续几何对照

查看实际裁片后，追加一个单独保留结果的实验：按检测到的轴对齐包围框从**原图**取像素，使用预先设定的 0/8px 边距，不再使用已经透视校正的裁片。四行 × 两种边距 × 三次 = **24 次**。

酒店名在两种边距下均变为“上海斯格威铂尔大酒店”，仍未恢复“曼”；其他行字符保持，数字仍粘连。这不支持仅扩大这个包围框就能修好，也不能彻底排除更精细几何处理的可能。

该后续运行同时重跑了前面的裁片与合成矩阵；没有把重跑当成新增独立样本增加覆盖率。

### 3.3 解码前证据

原批处理酒店行平均分数约 **0.929**，但输出“文”的时刻最高类别分数仅 **0.288**，blank 约 **0.233**、空格约 **0.080**。行均值掩盖了局部不确定性，不能仅用“整行高置信度”宣称每个字可靠；这些模型分数也不是经过校准的真实正确率。

结论：错误确实在字形识别端；本轮简单增强未解决。下一步有依据的方向是局部不确定性、裁切/归一化及识别模型候选，而不是固定全图跑六轮、挑一个看起来像答案的结果。

## 4. 假设二：数字间距与解码

### 4.1 64 个合成输入

为隔离字符识别与检测框影响，合成图直接交给同一识别模型，绕过检测器。矩阵：Segoe UI/Consolas、20/36px、黑白/金色深绿两种颜色、额外间隔 0/4/12/24px、两组数字 `25 29 35` 与 `12 34 56`，共 **64 项**。零间距基准为连续数字，不要求凭空猜分组。

评价使用数字组序列，不将尾随空格/重复空格误算为分组错误：

| 额外间隔 | 数字字符正确 | 分组正确 |
| --- | ---: | ---: |
| 0px | 16/16 | 16/16（连续数字） |
| 4px | 16/16 | 6/16 |
| 12px | 16/16 | 16/16 |
| 24px | 16/16 | 12/16 |

因此当前模型能认全数字，但组间空间表达不稳定；间隔更大不保证更好。不能从这组有限合成字体得出通用 12px 阈值。

### 4.2 原图门牌号时序

原图门牌行仍输出 `打浦路252935号`。模型所有时刻的空格类别最高分数约 **0.0145**，所以 greedy 解码没有输出空格字符；问题在结果页渲染前已经存在。

在数字区间观察到的相邻 token 间 blank 步数：

```text
2→5：2    5→2：5    2→9：3    9→3：5    3→5：3
```

这里确实仍有与组间距相关的时序线索，但 CTC blank 同时承担普通字符之间的间隔，不能直接转换成空格。当前解码生成字符框时用相邻中心的中点分界，两框会贴合，不再显式保留原始留白；下游又默认模型行内字符连续，无法可靠补回已丢失的分组。

### 4.3 纯逻辑机制测试

新增 `NskryOcrSpacingHypothesisTests` 验证：

- 长 blank 段不会自动变成文本空格。
- 真正的空格类别能被保留，解码器不是无条件删除所有空格。
- 中点字符框会接壤，不能把这些框当作真实像素紧包围框测留白。
- 当前布局会保留模型行原文；未凭答案补数字分组。

这是对当前机制的特征测试，不是“空格已修复”的验收。

结论：空间证据的保留/利用是最明确的下一步，优先级高于更换翻译模型。应保留时序或更真实的像素边界，再用独立多字体/号码/小数/长数字样本验证，不能硬拆 `252935`。

## 5. 假设三：翻译精度、解码与模型语义

### 5.1 216 次隔离推理

不经过 OCR，直接输入运行前固定的 12 个正确文本。2 个方向 × INT8/FP32 × beam 1/2/4，共 12 个配置；每配置六项文字各三次，共 **216 个结果**。

测试调用当前生产 worker 的校验、语言标记、分词、句子拆分和 token 上限，只通过测试适配器改变模型精度和 beam。每个配置单独进程，2 推理线程；进程内为对比保持一个模型加载，完成 18 次调用后退出。这不是新插件包的端到端 UI/冷启动测量。

所有配置的三次重复输出一致。普通截图指令正常，四次重复事件均保持四次，没有靠去重得到“正确”。但下列问题仍存在：

| 正确原文 | INT8 / beam 2 | FP32 / beam 2 |
| --- | --- | --- |
| 打浦路15号 | `15 Pour Road.` | `Call 15 Pour Road.` |
| 打浦路25 29 35号 | `25, 29, 35 Pour Road.` | `25, 29, 35 Pour Road.` |
| 这段文字使用12磅字号。 | `This text uses a 12-pound code.` | `This text uses a 12-pound code.` |

beam 增至 4 未统一修复，部分地址甚至丢了路名。原精度能改变措辞，不等于正确性必然改善。

另一个重要对照是 `Text is set in a 12-point font.`：全部配置都能表达为“12点字体”。这里“点”用于字体语境是合理表达，不能只因没有写“磅”就判错。它表明更明确的领域上下文会影响结果，不是引擎完全不认识数字或字体概念；原图片中的含糊翻译和中文“字号”误译仍是真实问题。

结论：翻译模型的领域/专名及上下文能力是独立问题；“仅因为 INT8 导致”或“只要增加 beam 就能好”的解释不受本轮支持。这个结果不证明更大模型一定更好，也不证明所有量化模型都一样。

### 5.2 资源代价与测量修正

完整矩阵第一次结果有效，但初版 hash 函数整文件读取模型，污染了进程内存高水位。因此改成流式 hash，并在结果/模型 hash 输出前记录峰值，完整重跑 **216 次**。两次文字输出完全一致；仅使用第二次资源结果，不挑有利输出。

第二次测试进程峰值范围：

| 诊断精度 | 工作集峰值 | 私有提交峰值 |
| --- | --- | --- |
| INT8 | 约 338–343 MiB | 约 850–854 MiB |
| FP32 | 约 558–563 MiB | 约 1040–1044 MiB |

这是 Python 诊断进程、一个模型跨 18 次调用的高水位，不可替代上轮冻结 worker 单任务约 653–655 MiB 的实测值，也不能据此声称产品内存回退。两边在同一测试框架下比较，FP32 有明显资源成本，而关键错误仍未消除；不能不经单任务实测就放宽产品 1 GiB 上限或默认切 FP32。

12 个测试子进程均退出。FP32 转换产物约 625 MB，保留在明确的 build 证据目录，不打入插件、不更改外置语言包。本轮没有低配实机数据。

## 7. 建议下一步

1. 优先实现有边界的空间证据保留与数字组恢复，再用小数、连续号码、代码、不同字体和间距作反例验证。
2. 对字形使用局部而非整行平均的不确定性，但本轮六种增强没有成功，不应将其直接变成生产多轮策略。
3. 翻译另建领域语义基准，比较适合的模型/引擎与来源上下文；保持按需释放，不以提高精度/beam 代替质量证据。
