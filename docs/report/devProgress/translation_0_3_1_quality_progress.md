# Translation 0.3.1：识别链路与翻译分段优化、同标准复测

日期：2026-10-25。开发试用版，不是正式发行质量放行。

## 1. 判断与实施顺序

对照 [上一轮验收](translation_public_image_audit_20261025.md)，优先级为：

1. **直接图片识别最严重。** 中文样本 CER 100%，原文几乎不可用；任何翻译引擎都不能从错误原文可靠恢复内容。
2. **视觉换行破坏语义。** 英文被拆成 8 行分别翻译，既破坏连贯性，也增加 MyMemory 顺序请求耗时。
3. **离线模型调用/分段仍有独立缺口。** 正确人工英文去除软换行后，4 次事件曾译成 8 次；不能全归因于 OCR。

先用现有原生识别 worker 对两张图做原样探测，确认显著优于原始 Windows OCR 后，才接入翻译包。该探测的空 regions 仅用于导出原始结果，不是准确性验收。正式复测仍使用先前冻结的人工标准。

分阶段保持可构建：先接入识别与几何布局，再更新离线分段、模型标记与测试，最后打包、解包、完整回归及真实图片复测。没有一次性重写 OCR、采集或翻译插件。

## 2. 实际改动

### 2.1 独立按需识别，消除较差的直接识别旁路

- 抽出 `image_recognition.cpp/.h`；默认构建使用现有 PP-OCRv4 原生 CPU worker。
- 复用 OCR 的源码/静态协议与布局算法，构建期复用固定模型资产；翻译包拥有自己的 `ocr/`、worker、运行库、模型及许可证声明。
- 不加载 OCR 插件 DLL，不查找其他已安装包的私有路径，不要求安装 OCR/长截图插件；没有新增 Core 重模型或跨插件服务协议。
- 一次任务一次识别，退出识别 worker 后才启动离线翻译。没有固定多轮 OCR、预热、空闲模型池或新后台常驻任务。
- 输入继续最多 4096 × 4096 且不超过 4 MP；借用图返回前复制，后台只处理自有像素。识别进程继续使用既有受限协议、1 GiB Job 私有内存硬上限、最多 4 线程和本次 20 秒识别上限。
- 使用同一 `BuildTextLayout` 几何规则重建段落，区分附近续行、列表与远距列，不盲目合并所有换行。OCR→翻译已有文字交接不重新运行识别。
- 保留 `NSKRY_OCR_MODEL_ENGINE=OFF` 的明确无模型构建，使用 Windows OCR；它不是准确识别失败后的静默回退。默认包缺私有资产时明确报错，允许用户粘贴原文，不伪装识别成功。

### 2.2 修复离线模型输入与句子单元

- 核对外置语言包自带的固定版本模型卡及词表，发现 en→zh 多语模型明确要求源端目标语言标记。补入 `>>cmn_Hans<<`，不把它当普通文本交给 SentencePiece 拆字。
- 验证转换后词表含该标记；缺失/损坏或过大的词表返回明确加载失败。该标记与 EOS 均计入原有 256 token 上限，未提升推理预算。
- 在几何段落之后按完整句子作离线推理单元，过长句子仍使用原有无损、重新分词校验的切片和输出触顶重试。
- 保留原文重复句，不使用 n-gram 禁止重复或输出去重；没有“狗/狐狸”、酒店名、门牌号等样本硬编码，也没有词典式纠错。
- 沿用一任务、2 翻译推理线程、最多 128 次调用、60 秒翻译上限、加密临时文件、取消/关闭 Job 回收与旧成功回复兼容。
- 已有文字的硬换行仍保留；没有几何信息时不猜测它一定是软换行。所以原样人工 8 行文本对照仍可能断句，不能将该情况宣称为已解决。

### 2.3 包与兼容性

- 版本更新至 0.3.1；API 2、reserved、文字翻译交接 v1、已保存配置均不变。
- 两种包 ID/version 相同，用户选择其一，不是同时安装两个插件。在线专用仅省略离线**翻译**运行时，仍自带本地**识别**模型，因此包体积增加。
- 构建生成 `image-model.txt`；打包工具检查配置与 `--without-image-model` 一致，防止漏打准确识别资产。
- 既有外置 OPUS 模型不需重新下载/转换；必须更新完整匹配 worker，不能只替换 DLL。
- 本轮没有扩展在线提供者、修改收费/确认上传规则或设置默认联网回退。真实在线只复测 MyMemory；没有用户 Key 或真实 LibreTranslate 服务，不声称其线上质量已验收。

### 代表性输出与仍未通过的内容

英文识别现在为完整的测试说明段落和连续的 4 次狗跳过狐狸事件。离线译文为：

```text
这是很多12点的文字 测试ocr代码 并看看它是否工作 在所有类型的文件格式。

一只棕色快狗跳过懒狐 一只棕色快狗跳过懒狐 一只棕色快狗跳过懒狐 一只棕色快狗跳过懒狐
```

原文不再缺字，事件次数、主客体保持，但译文仍生硬，句末标点有丢失；`12 point` 仍未明确译为字体字号。在线英文较连贯且保持 4 次事件，也仍将字号表述为“12点文本”。**英文 OCR 通过，不等于英文翻译全部语义项通过。**

中文原文：

```text
上海斯格威铂尔文大酒店

打浦路15号

绿洲仕格维花园公寓

打浦路252935号
```

`曼 → 文` 及数字分组缺失尚未解决。在线译文末行是 `252935 Tupo Road`；离线更出现 `Two hundred and twenty-nine thirty-five at Plum Road.`。不能当成正确地址。

人工完全正确中文对照仍会将打浦路译为 `Pour Road`（离线）或 `Tupo Road`（MyMemory），说明专名/路名另有翻译模型或服务层问题，不能仅修 OCR 后宣称解决。

## 5. 资源与释放

主矩阵顺序运行。扩展开发测试采样器，分别记录本进程的 OCR/翻译子进程，并记录同一时刻父进程 + 存活子进程的采样值，不将两个阶段的独立峰值相加。

- 每个真实图片任务观测到 1 个 OCR worker；离线任务另有 1 个翻译 worker，在线任务没有翻译 worker。
- 同时存活子进程采样峰值 **1**，全部观测句柄任务后均已退出。代码顺序也确保识别进程结束才开始下一阶段。
- OCR worker 私有提交采样峰值约 **176–212 MiB**，工作集峰值约 **181–207 MiB**。
- 离线翻译 worker 私有提交峰值仍约 **653–655 MiB**，工作集约 **150–152 MiB**；没有因本次修复显著降低模型加载峰值，不以权重体积冒充 RAM。
- 主矩阵同一时刻父进程 + 子进程最大采样私有提交约 **657 MiB**、工作集约 **235 MiB**；不是分别取最大值再相加，也不是系统所有进程用量。
- 父进程私有提交约 5–11 MiB、工作集约 18–29 MiB，包含测试窗口/观察器。
- 观察器 20 ms 内存采样、100 ms 进程发现均仅存在于测试中，未加入产品。观察开销未扣除，采样不能保证捕获每个瞬时尖峰。
- 开发机 CPU：i7-12650H。没有低配实机数据；本轮部分任务超过 2 秒，**不宣称低配或所有任务均能 1–2 秒完成**。
- 包体积增长是准确本地识别资产的代价；两个插件同时安装会有磁盘资产重复。去重服务属于未来有明确契约的规划，本轮不偷用另一个已安装包来省空间。
