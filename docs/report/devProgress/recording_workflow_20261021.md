# 录屏 0.3.0：交付、窗口跟随、GIF 与录后裁剪

日期：2026-10-21。基线 `40e0a1e`（0.2.0），所有更改保留在工作区；未安装用户插件、未停止用户程序、未提交/push。

## 1. 核对及完成范围

原实现确认是固定屏幕坐标、20fps、录前保存对话框，没有GIF、窗口跟随和录后裁剪。
复用已有Timeline、帧调度、专属MTA采集线程、隔离MF编码进程及Job取消/收尾，未重写截图/监控采集模块。
规范先完整核对 `core_plugin_contract.md`、`development_standard.md`，再核对实际SDK、采集、入口与测试。

| 用户项目 | 本轮实现 | 边界 |
| --- | --- | --- |
| 1 录后保存/剪切板 | Stop后显示Save/Copy file/Trim/Discard | CF_HDROP文件，不是位图；真实目标软件粘贴兼容性待验 |
| 2 可选窗口跟随 | 录前Follow selected window，窗口WGC源+相对DWM选区 | 同显示器、同DPI、同大小移动；其他变化明确结束，不换源 |
| 3 实际录制提示框 | 新增实际物理选区红框，跟随worker上报bounds，排除采集/鼠标穿透 | **部分完成：Windows自带整屏/整窗口边框仍存在，不宣称彻底解决** |
| 4 调整前后范围 | 录后Trim输入起止秒数、Apply；后台重新编码，原文件失败时不变 | 非可视化多轨编辑，非无损裁剪；GIF按百分之一秒量化 |
| 5 三档码率 | 高清/高/中、录前快选及保存默认值 | 分辨率/fps自适应目标码率，不是瞬时硬上限 |
| 6 两档帧率 | 30/60 fps、录前快选及默认值 | 显示实际平均fps/目标fps，不承诺低配达到60fps |
| 7 GIF独立按钮 | 同一record包声明Record GIF额外动作，不在视频入口选格式 | 固定10fps、RGB332、960/540边长上限、约两分钟 |
| 8 大选区工具栏 | 所属显示器内布局、空间不足放进选区、小屏自动换行 | 截图从原snapshot导出，overlay另加capture-exclusion |

设置入口：Settings → Plugins → 选中插件 → Plugin settings。元数据发现不加载DLL；主动点击才加载并展示，
不启动采集、编码或模型。录前Save defaults也可保存。默认30fps/High，单个版本化DWORD原子写入插件私有HKCU key；
损坏/未来版本值拒绝覆盖，未知其他配置保留。

Windows系统边框是WGC的源边界，不是实际裁剪RECT。
[Microsoft IsBorderRequired说明](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.graphicscapturesession.isborderrequired)
要求禁用前取得Borderless许可并声明相应包能力；本工程当前发行形态未完成这条授权路径。
本轮保留系统指示、增加准确红框，不能把两者混为“系统全屏框已移除”。后续可评估合规授权/独立桌面采集后端，未提前加入空接口。

## 2. 结构与兼容

- Core：区域采集v2、声明式额外capture动作v1、插件设置UI v1、框选工具栏布局。
- Plugin：选项/控制/结果页、文件交付、GIF/WIC编码、MF重新编码裁剪；没有新增插件前置。
- API2两个公开结构及reserved不变，v1采集/主execute/command/input配置确认接口保持兼容。
- 0.3包明确声明 `region_capture:2`，需要同轮Core；旧宿主拒绝，不仅更新DLL、不静默退化采集语义。
- 原standalone保留位、跨插件依赖、未来API3跨surface动作未启用。
- 新SDK与包规范见 [扩展说明](../../plugins/recording_extensions_v2.md)。私有worker协议仍不是SDK。

选区/输出仍为物理像素，输入总像素≤3840×2160，WGC源帧池另限16MP/8192单边，防止巨大窗口分配无界帧池。
跟随源在read核对HWND线程/PID、Closed、大小、DPI和显示器，暂停后按原偏移重开并验证尺寸。
更改尺寸、最小化、关闭、跨屏时尝试收尾不完整片段，保持失败标记，不冒充完整保存。

## 3. 文件与资源

- init/设置/录前选项不预热；开始后才创建线程/采集/编码进程。
- 视频0.5–24Mbps，高清/高/中除数4/7/12；硬件优先并真实查询后端，保留软件降级。
- GIF固定256色RGB332逐帧WIC编码，单帧索引缓冲，不缓存全部动画。写帧前检查128MiB，可能多出最后一帧的写入量。
- 视频共享槽最大3,110,400字节；GIF BGRA槽最大2,073,600字节；帧池2帧、两张BGRA；无无限帧队列。
- 暂停释放采集、取消等待计时器、事件唤醒继续；编码进程保留，暂停时间不写成视频空白。
- 普通编码调用15秒、Trim最多5分钟，均可由取消事件打断；只结束自己创建的Job，512MiB进程提交上限不等于显存上限。
- 保存/裁剪在按需ExportTask中做，不阻塞消息循环。缓存建目录/有界容量检查也在worker，不在UI扫描。
- Trim在隔离子进程中MF/WIC解码+重编码，校验尺寸/有效显示区域，处理160×90→160×96等编码填充，不把补齐边缘作为新图像尺寸。
- 暂存/发布/失败/退出清理自有随机文件；退出与裁剪刚完成竞争时也回收未交付的新缓存。保存目标始终不覆盖。
- CF_HDROP加Preferred DropEffect=COPY；发布成功的缓存文件保留至用户自行清理，避免退出破坏粘贴/剪贴板历史。
- 开始下一条/裁剪前检查缓存1GiB、2048项预算；不驱逐已复制文件、不加后台清理线程。单条MP4仍需用户保证磁盘空间。
- Core WGC/D3D以及文件系统调用仍有系统级永久阻塞边界；不宣称隔离了所有驱动/内核行为。

## 4. 验证

Release在独立 `build/verify` 构建，生成新 `.nskryplugin`，不覆盖正在使用的用户程序、不安装包。
完整已有测试与新增测试共30项；最终结果见下方“最终验证记录”。

新增/扩展回归包括：

- 三档码率、30/60参数、版本化默认值、坏/未来版本值、Trim区间/样本交集/溢出、60fps调度。
- 元数据额外动作/重复ID/未知扩展拒绝、未加载发现、主动作兼容、无声明动作拒绝。
- 插件设置UI用户点击才打开、不采集；设置页按钮大小/布局/服务交付。
- 实际额外动作从框选按钮交付独立actionId；大选区工具栏/小屏换行。
- 真实MF软件60fps：60帧，1.000000秒；裁剪0.2–0.8秒，解码36帧，0.5999833秒（允许10ms误差）。
- 真实WIC GIF：10帧1秒；裁剪后6帧0.6秒；逐帧解码与延迟/颜色检查。
- 完整GIF RecordSession的暂停释放采集、继续、停止、动画时长、worker退出。
- 后台保存、取消保留源文件；原有编码进程崩溃/挂起/Finalize挂起/存储失败/恢复和取消竞争仍通过。
- 真实WGC测试自建窗口：移动后bounds跟随、暂停后移动再继续、尺寸变化及源关闭明确失败；不录用户应用。
- 录后Save/Copy/Trim入口、取消Trim返回、丢弃清理；GIF入口固定参数禁用；三档/两档选项列表。
- 原截图、监控、Core编辑、OCR快/精确、更新和插件输入生命周期测试仍运行；长截图插件构建通过，真实长截图交互未在本轮手动验收。

测试机：i7-12650H、16逻辑处理器、约16GiB内存、RTX4060 Laptop，**不是低配机**。
本轮测试是短时功能/生命周期验证，不是独占环境性能基准，不能把0.2的20fps基准拿来证明0.3的60fps/GIF低配表现。
尚无0.3完整宿主+子进程CPU/RAM/GPU峰值、稳态和真实2C/4T/4GiB机器的测量结论。
