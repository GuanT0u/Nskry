## 2. 已有网站与设计目标

当前为 Astro 静态网站，21 个 HTML 页面，四个插件详情、八篇教程。
包括首页、下载、插件列表/详情、教程、版本历史、开发者入口、关于、公告和 404。
无后台、账号、数据库或访客追踪。现有低饱和绿色样式仅是初版，不是必须保留的最终品牌色。

目标是整洁白板上的手写标注、记号笔边线、少量便利贴与手绘箭头，体现轻巧、清晰、可操作。
白板风用于空间、结构和信息层级；手绘风用于边线、图标、强调和插画。
主按钮、导航和正文要容易辨认；不要把整个页面做成随机歪斜的草稿。
官网用于软件下载、插件选择与教程阅读，不增加自由拖拽白板、画布编辑器或无限缩放。

首页现有图为明确标注的交互示意。可以重新绘制，但不能将其冒充实机截图。
真正的软件截图只能使用有来源、脱敏且与当前功能一致的素材。

## 3. 先制定视觉规则，再逐页实现

第一阶段先新增 `website/DESIGN_SYSTEM.md`，并建立集中式 CSS tokens（如 `src/styles/tokens.css`）。
完成一页基础组件样例，展示规则后再应用到全站。无需等待逐项批准，可由设计 agent 自审后继续实现。
样例可以是本地 QA 页面；若放入静态输出必须注明其用途，且不能改变产品路径或混入正式导航。

规则至少包含下列内容，必须填写明确的数值、颜色、用途与例外，不能只写“适当阴影”“字体稍粗”。

### 阴影

- 先确定统一方向、光源和风格：以轻微偏移的实色/低模糊阴影表达纸片或白板贴片。
- 定义无阴影、普通卡片、悬浮/选中、弹出层等有限等级，并逐级给出 x/y 偏移、blur、spread、颜色和 alpha。
- 说明默认、hover、active、focus 各状态的变化；按下可收小偏移，键盘焦点不能只靠阴影辨认。
- 正文、图标不统一加文字阴影；不要用大范围多层模糊、持续动画或大量滤镜制造立体效果。
- 装饰阴影与真正的层叠顺序分别定义；不要靠任意加大 z-index 修补遮挡。

### 字体与粗细

- 分开定义展示标题、正文、按钮、导航、标签、元数据、代码的字体族、字号、行高和字重。
- 建议正文以 400、功能控件以 500/600、重点标题以 700 为起点，最终按实际字体可用字重确定。
- 手写字体优先用于短标题或少量注释；中文教程正文使用清晰、覆盖完整的字体。
- 不依赖浏览器伪粗体来获得实际不存在的字重；不要全页粗体，也不要用细浅文字堆出“高级感”。
- 默认系统字体即可。新增字体须说明来源、再分发许可、字符覆盖、文件体积、fallback 和 font-display。
  避免外部字体 CDN 和未经评估的整套大体积中文字体。

### 配色与明暗层级

- 确定白板底色、纸片底色、主文字、次文字、边线、主强调色和状态色的语义 token。
- 为每个颜色列出明确色值，可附 OKLCH 明度；说明背景/文字的配对和实测对比度。
- 要形成稳定明度顺序：背景较亮、面板能区分、正文足够深；主次文字不能仅通过极低透明度区分。
- 项目验收目标：普通正文对比度至少 4.5:1，大字至少 3:1；必要的控件边界和焦点标识至少 3:1。
- 半透明高亮和底纹须在实际叠加背景上核对；白板网点不能干扰文字阅读。
- 成功、警告、错误、选中同时用文字/图标/边线表达，不能只凭颜色。
- 首版以浅色白板主题为主，不因视觉改版额外加入完整深色主题需求。

### 手绘笔触与版式

- 统一边框粗细、圆角、不规则程度、间距和图标尺寸。手绘扰动应固定可复现，不在每帧随机计算。
- 内容块保持稳定对齐，倾斜和粗糙边线仅用于装饰，不歪斜长段文字、表格或点击区域。
- 优先用 CSS 或少量本地 SVG；装饰设为不接收点击，并提供合适的无障碍隐藏标记。
- 定义窄屏布局、触控点击区域、减少动态效果模式。无需动画即可理解全部内容。

| --- | --- | --- |

## 5. 必须保留的行为

- 下载与阅读不依赖 JavaScript；筛选是渐进增强，脚本失败时仍显示完整列表。
- 无正式资产就显示待开放；无第三方条目就如实显示，不为排版伪造插件、评论、下载量、评分或认证。
- 开发版、正式版和撤回状态清晰；开发记录日期不能重新解释为正式发布日期。
- 在线/离线翻译包说明保持明确，不能隐藏运行时/语言模型差异来简化页面。
- 官方更新目录只在 `.astro/catalog-preview/` 本地生成，不进入 dist；不新增公开 catalog 路由或客户端配置。
- `WEBSITE_BASE=/` 与 `/Nskry/` 都能构建和导航；链接继续使用现有 helper。
- 不新增在线分析、远程字体、账号、支付、评论、远程安装或常驻动画循环。
- 不移除错误、风险或隐私信息来美化截图；可以优化这些信息的排版与长度，但保留实质含义。

## 6. 实施顺序与验收

1. 隔离工作区并记录基线；读取实际实现。
2. 写设计系统，确定阴影、字重、配色明暗与笔触 tokens，做按钮/卡片/提示/正文样例。
3. 完成首页和通用布局，再覆盖下载、插件列表/详情、教程、版本历史、开发者、关于、公告、404。
4. 自审代码边界和资源，执行测试与页面验收。
5. 交付修改清单、截图、测量及已知问题，等待主 agent 审核与合并。

在自己的 `website/` 目录运行：

```powershell
npm ci
npm test
$env:WEBSITE_BASE = '/'
npm run build
$env:WEBSITE_BASE = '/Nskry/'
npm run build
$env:WEBSITE_BASE = '/'
npm run build
npm run catalog:preview
git diff --check
```

当前参考值：10 项逻辑测试、21 个 HTML 页面、323 处本地引用、根路径 dist 总量 59,838 字节。
这些是基线数据，不是要求冻结测试数量或不允许增加资源；说明前后差异及原因即可。
要报告新增 JS、字体、图片及总输出字节，不以压缩后的局部资源代替总量。

至少检查 390px、768px、1280px 宽度，以及 200% 页面缩放；长标题、长 hash、代码块不能撑破页面。
验证插件搜索/无结果/类别过滤、下载待开放、撤回显示、教程导航、404 和键盘 Tab/focus。
检查减少动态效果设置，正文阅读与关键操作不依赖 hover。
无下载资产或撤回样例时，用隔离 QA fixture 验证组件，不污染正式发布数据。
未完成的浏览器、无 JS、屏幕阅读器或硬件检查必须列为未验证。
测试完成关闭自己启动的临时服务；不终止用户已有进程。
