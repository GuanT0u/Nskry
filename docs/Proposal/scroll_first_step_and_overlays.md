# 长截图首步失败、悬浮按钮和固定栏的排查与改进顺序

2026-11-21。核对范围为长截图插件 0.5.4 工作区和 0.5.3 提交 `acfe588`。本机已安装的 DLL 与 0.5.4 构建产物的 SHA-256 一致。现有成品图没有记录当次进程加载版本、滚动方向、每步位移或采集时间，下面区分成品证据、回放复现和现场待证假设。

## 五张图提供的证据

- 用两张右下角示例图中的按钮细节分别匹配两张含球长图，按纵坐标合并重复响应。相关系数超过 0.93 的独立位置至少有 14 个和 12 个，每张图中这些位置的横坐标相同。按钮确实多次进入了输出。
- 无球长图中的顶部通知栏和底部输入栏可见。取右侧背景的 95 × 8 像素块，块内有 325 种颜色；在 y=737、835、886、937、987、1087、1097 七处逐像素相同。排除了单色空行自然重复这一种解释。尚不能把每条横线具体归到输入框边界、壁纸接缝或错误位移。
- 两张示例图来自不同聊天界面，不能互作前后帧。含球与无球的成品选区也不同，不能直接用两组成品计算悬浮球对失败率的影响。

## 首步回放

从两张示例图截取素材，合成位移已知的相邻视口。每种条件 50 对，来自两种画面、五个起点及 3、12、27、48、70 px 五种向下位移。调用插件的实际匹配、接缝和合成代码。对照仅改变指定变量；这些数字描述回放样本，不估算线上成功率。

| 条件 | 0.5.4 结果 |
| --- | --- |
| 整数平移，只有正文 | 50/50 位移正确且成品逐像素正确 |
| 同一正文，右下角叠加固定按钮图块 | 50/50 位移正确且成品逐像素正确 |
| 加入模拟半透明顶底栏 | 28/50 得到正确位移并提交 |
| 半透明栏再叠加按钮图块 | 22/50 得到正确位移并提交，其中 21 幅与理想参考逐像素一致 |
| 只有正文，新帧取相邻两行的均值，模拟半像素采样差异 | 0/50 通过位移误差门槛。单独给接缝函数输入正确位移附近的两个整数，50/50 都能找到接缝 |
| 用固定纹理覆盖部分视口，仅消息区域移动 | 14/50 得到正确位移并提交；34 次被固定纹理保护拒绝，另有一次位移评分失败、一次接缝失败。0.5.3 同组给出 49/50 正确位移，旧版的这个数字只评价位移 |

0.5.3 同样拒绝了所有半像素样本。固定纹理保护是 0.5.4 新增的拒绝来源；纯正文在重采样后失败，则有更早的原因。另做离线可行性实验，将当前帧分区，在各区选择有纹理的小块，以平滑后的局部灰度相关性投票。在上述半像素样本中，37/50 给出距真值半像素的位移，13 次弃权。周期图案和无关图各一个负例均弃权。这个实验支持继续评估局部匹配，还不足以替换现有算法。

## 原因、可信度和区分方法

| 机制 | 判断 | 能区分它的实验 |
| --- | --- | --- |
| 采集起点和时序 | 宿主传入框选时的冻结图，插件后续每约 90 ms 由桌面采集。进入插件前后的悬停、覆盖层、动画或内容变化均可能使首次比较失真。拒绝后继续相对最后成功帧匹配，用户继续滚动可能耗尽重叠。机制可从代码确认，现场触发率未知 | 同时比较冻结图→第一张直播帧和直播帧→下一张直播帧；记录首次输入、实际帧间隔、候选位移。若后一组稳定，先修启动交接 |
| 位移评分对文字渲染过敏 | 匹配器对有边缘的像素计算 RGB 误差，正文文字边缘恰好对重采样敏感。纯正文的受控失败已定位在最佳误差门槛，尚无证据表明用户现场必然有半像素位移 | 对同一组原始帧同时给出当前评分和局部匹配结果，保留零位移及第二候选，检查静止动画、重复行和反向误判 |
| 悬浮按钮与半透明固定栏 | 底部按钮的位置固定，按钮下的消息仍会滚动；半透明输入框内的像素也会跟随底层内容变化。现有顶底检测从边缘逐行扫描，任一采样点变化就可能提前结束。简单按钮可拼好，按钮与固定栏组合明显降低成功数 | 保持选区、滚动起点和输入序列完全一致，独立开关按钮、顶栏、底栏、壁纸。分别记录位移是否正确、边界是否正确、输出中按钮出现次数 |
| 合成与位移共用全局假设 | 局部消息可以给出可靠位移，而静止纹理足以否决整帧。反过来，找到一条相似横行也不能保证其后复制的整个区域都属于滚动正文。已复现两种判断目标不等价 | 把已知真实位移直接送入合成器，单独检验消息文字、接缝、固定栏和按钮的像素；用上、下、折返三类轨迹检查历史边缘 |

## 推荐实施顺序

1. **先让第一次失败可定位。** 在插件会话内保留有上限的数值记录，区分未产生移动、搜索不到位移、候选歧义、固定纹理冲突、没有接缝和重叠不足。正常使用不写聊天图。调试时仅由用户主动导出指定帧对。保留宿主首图供未滚动时复制；在显示控件并排除遮挡后，用插件自己的采集路径取得一次实时基准。只有证据表明页面尚未滚动或仍可连接，才可切换基准，避免丢失开头。
2. **恢复纯正文的首步成功率。** 保留低成本整数匹配快路径；失败时在有限个有纹理的局部区域做归一化匹配，要求多个相隔的正文区域支持同一位移。位移判断与输出质量各自给出结果。再用一张临近帧验证有歧义的首步，处理小数位移累计，防止每帧取整最终漏掉整行。只有中间帧能连回最后已提交位置才允许补接。
3. **分别处理边缘栏和局部遮挡。** 顶底栏用多列分隔线及跨帧稳定性估计，容许插入光标闪烁。悬浮球作为有面积上限的局部遮挡，用同屏坐标与对齐后坐标的误差区别于正文。优先从相邻帧该位置露出时取真实像素，首端导航、末端输入框、边缘按钮各保留一次。若正文始终被遮住，保留已确认内容并提示重选。连续固定壁纸、半透明前景分层单独验证。
4. **给像素证据不足的页面一条简单退路。** 在插件预览中临时指定“用于匹配的正文区域”或忽略一处浮层，仍用所选输出范围合成。用户能在成功前看清最终裁剪范围。浏览器 DOM 或特定应用抓取可作为将来的独立采集方案，首轮通用修复无需新增权限、网站适配或插件依赖。

## 项目边界与验收

采集时序和用户提示由 `nskry_scroll.cpp` 管；正文位移与置信证据由 `scroll_stitch.h` 输出；`scroll_composite.h` 负责验证重叠、选择可见像素并提交。三个职责都保留在长截图插件内，沿用现有 Core、API 2 和内存预算。给昂贵回退限定候选块数和调用次数，只有活动会话持有短帧历史。离线实验用了 OpenCV；部署方案可直接实现所需的少量局部评分运算。

验收分开记录**首步正确率、已接受位移中的错误数、最终正文缺行/重复行、固定控件次数、匹配耗时 P95 与峰值内存**。整数干净对照须保持逐像素一致；新方法必须优于当前重采样基线，静止动画、无重叠、重复内容和快速反向滚动不能因此被误接。现场复测应包含手动滚轮和触控板，在同一窗口固定选区分别切换浮层与栏位。若只能补充一组现场材料，优先要第一次失败时的连续三张非敏感原始视口及各步拒绝原因。

ShareX 公开说明了静止元素和悬停变化会妨碍匹配，也区分首次失败与部分成功；可借鉴它的失败反馈。Android 的滚动捕获会话由应用提供滚动边界；通用 Win32 截屏可以借鉴这一职责划分，但需要自己估计或让用户指定边界。[ShareX 官方说明](https://getsharex.com/docs/scrolling-screenshot) · [Android ScrollCaptureSession](https://developer.android.com/reference/android/view/ScrollCaptureSession#getScrollBounds())

## 0.5.5 实施记录

选区关闭后、长截图控件显示前，插件采集第一张实时帧。首次有效扩展前，用户仍可复制或编辑原框选图。首次扩展成功后，成品从进入长截图时的实时画面开始。

保留原有整数匹配作为常见情况的快路径。失败时，通过稀疏的灰度采样在最多 25 个局部位置寻找纵向位移。搜索包含零位移，只有多个纵向区域支持唯一且一致的非零位移时才尝试拼接。两帧的辅助采样最多占约 1.32 MiB，匹配结果仍需经过固定纹理检查和重叠接缝检查。插件自身实现相关性评分，现有运行包无需图像处理库。

半透明边缘允许以两帧中都存在的宽分隔线推断边界。接缝从重叠区中央开始搜索，遇到局部遮挡时会检查更宽的范围。新扩展的一端及该端固定栏使用同一帧，避免悬浮按钮与半透明栏交叠处由两帧切开。

| 原回放素材，每组 50 对 | 0.5.4 | 0.5.5 |
| --- | ---: | ---: |
| 整数平移，仅正文 | 50 | 50 |
| 整数平移，右下角固定按钮 | 50 | 50 |
| 半透明顶底栏 | 28 | 37 |
| 半透明顶底栏加固定按钮 | 22 | 34 |
| 纯正文，模拟半像素重采样 | 0 | 39 |

前四行是成功提交数。0.5.5 接受的前四组样本均与各自理想成品逐像素一致。最后一行是接缝通过且位移在已知真值附近的样本数。该组每对独立比较，不能用来推断连续小数位移的累计误差。真实页面上的触控板采样、复杂壁纸与消息分层仍需原始相邻帧复测。终点栏来源及重采样文字已加入纯逻辑回归。
