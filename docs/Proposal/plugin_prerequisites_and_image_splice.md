# 前置插件与通用图片区段删除规划

> 2026-10-12：区段切除/拼合已在 Core 实现，见 [实施报告](../report/devProgress/resource_first_features_20261011.md)。
> 跨插件依赖解析/服务协商仍是未来协议；本文保留 2026-10-10 的边界选择及实施顺序。

日期：2026-10-10。补充现有边界规范，不修改 API 2 ABI，不宣称以下能力已实现。

## 1. 前置插件允许，但不能隐式捆绑

允许独立的服务插件成为前置。划分依据是能力职责、资源生命周期及可独立测试性，不是文件大小。
共享重引擎/模型服务可以独立交付；普通编辑/裁剪/复制已属于 Core，不为其再要求安装滚动采集功能。
一个大插件内的私有小能力不是公共服务；确需共享时先抽成职责单一的库或服务包。
不能为了复用一个小模块强制安装并启动录屏/滚动/上传等无关功能。

设计审查必须列：单一职责、提供的服务及版本、依赖用途、缺失影响、用户可替代选择、idle/峰值预算。
允许必需和可选前置；可选前置缺失仅隐藏相关扩展，不影响其它功能。必需前置缺失应明确拒绝相关动作。
专用无 UI 服务也可存在，不强制为了出现在工具栏而伪造动作；它的启动与停止仍由宿主管理。

## 2. 实施顺序：先协议与解析器，再使用方

1. 设计版本化 manifest 依赖与服务声明：插件 ID、版本范围、必需/可选、服务 ID/协议版本；先评审再定 schema。
2. 只读 metadata 建依赖图，检测循环/自依赖/版本冲突/服务冲突；未执行动作不加载 DLL/模型。
3. 安装前展示完整最小依赖集合、来源与大小，由用户确认；不从任意插件 URL 自动执行安装。
4. SDK 下一版本提供服务查询、句柄/所有权、线程规则与生命周期协议；禁止目录猜测、窥探 HWND、裸互调导出函数。
5. 禁用/卸载/更新显示依赖者影响，定义更新原子性与重启顺序，拒绝产生半可用状态。
6. 服务按需加载，任务结束回收工作资源；通用服务不等于允许常驻模型。
7. 集成缺失/冲突/循环/失败回滚/部分初始化/取消/退出测试，然后才交付依赖插件。

当前 `requires_plugins` 拒绝检查必须保留，直至以上协议真实可用。
不把未来字段塞进 API 2 reserved 指针，也不让安装器先“支持”宿主无法运行的包。

## 3. 图片中段切除：建议 Core，而非 Scroll 前置

**归属建议：Core Image Editor 的按需、通用结构编辑操作。**
对普通截图、钉住图、监控的静态帧、OCR 原图、长图同样有用；算法不需要滚动采集或 OCR 引擎。
Scroll 仍只负责采集/拼接，产物交给 Core。无需为了普通图去装 Scroll。
这轮仅确定规划，不开发工具按钮或像素操作；若后续扩展为复杂多轨合成，可另做专用插件，不能把重编辑器塞入 Core。

### 处理范围

- 上下：两条水平切线，删除完整宽度的行区段，将上/下剩余像素拼接。
- 左右：两条垂直切线，删除完整高度的列区段，将左/右剩余像素拼接。
- 两个方向复用同一操作模型，UI 显式选择方向；默认水平切线，适合删除长图广告/评论。
- 不支持任意矩形挖空后智能补图、不拉伸压缩文字、不做 OCR 内容纠错。
- 多个区段需要有序、互斥的范围表示，按原图坐标处理；不允许全部删除或输出零尺寸。

### 编辑与资源边界

两次切线选择 → 预览将删区段 → 确认/取消 → 更新画布；每次可撤销/重做。
“压缩”是删除像素并缩短宽/高，不是有损缩放。输入、输出像素预算与溢出检查必须明确。
按需处理，无驻留 worker；预览优先画遮罩，不在每个鼠标移动时复制整张长图。
确认时分配结果，撤销采用有界历史/区段记录，不能无限持有全尺寸位图副本。

结构编辑须与裁剪、旋转、平移缩放统一坐标变换；跨切线的标注如何裁切必须先定义。
OCR 文本/框坐标不得复用为编辑后结果：改变像素后重新识别或明确标记失效。
监控只编辑当前静态帧，不改变原监控范围；复制/保存/固定均使用最终确认图像。

### 验收

不装 Scroll/OCR 也可编辑；上下/左右切除、边界、单像素、反向选线、多段、撤销重做、缩放坐标、
大图内存限制、复制保存尺寸、取消恢复、标注/OCR 失效均有测试。
未来若允许插件贡献 Core 编辑器工具，应另设计版本化 Editor Tool 接口；现有 post_capture 不等于工具注入接口。
