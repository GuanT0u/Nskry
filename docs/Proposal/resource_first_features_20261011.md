# 区段拼合、聚焦隐藏、悬浮窗视觉：资源优先总案

> 2026-10-12 状态：推荐路线首版已实现，见 [实施报告](../report/devProgress/resource_first_features_20261011.md)。
> 下方保留 2026-10-11 设计比较和目标；低配、多屏、真实监控性能及 DComp 对照仍待验收。

日期：2026-10-11。范围：先比较方案和确定推荐，不修改程序运行行为，尚未做原型/性能实测。
每个功能比较至少三种实现角度，保留推荐路线的判断依据。

## 1. 分案入口

1. [图片区段删除与拼合](image_splice_resource_options.md)：即时像素重建 / 非破坏区段映射 / GPU 拼接。
2. [聚焦监控源时隐藏](pip_source_focus_hide_options.md)：WinEvent / 定时轮询 / Shell 激活消息；另比较隐藏后的三种采集资源策略。
3. [阴影与圆角](floating_window_visual_resource_options.md)：DWM 系统基准 / 几何缓存与区域裁剪 / DirectComposition / CPU 整窗 alpha。
   DWM 不能完整实现自定义参数，明确不把它算成完整方案；其余三条覆盖自定义需求。

## 2. 推荐结论

| 功能 | 目前资源优先推荐 | 主要理由 | 保留风险 |
| --- | --- | --- | --- |
| 中段删除并拼合 | Core、非破坏区段映射，CPU 按需输出 | 多次编辑不保存全图快照；不驻留 GPU 副本 | 映射/拼缝/历史及导出内存需严格测试 |
| 聚焦源暂时隐藏 | WinEvent + 即时软暂停 + 稳定隐藏后回收会话 | 无主动焦点轮询；长隐藏减少持续采集 | 重建延迟/峰值、源身份、菜单及最小化状态 |
| 阴影 | 缓存几何边片，只按窗口几何/参数变化更新 | 不按监控每帧 blur；不持完整透明中心缓冲 | 多辅助 HWND 成本与跨窗口输入/z-order |
| 圆角 | Win11 默认原生偏好；自定义 region，质量不合格升级 DComp clip | 不改 PiP 的 GPU 内容链路；几何变化才更新 | 原生启发式不保证，region 边缘可能阶梯 |

这是**基于当前代码与算法的工程推断，不是测得的普适性能排序**。
如果只需系统默认外观，纯 DWM 自有资源最低；但它不满足自定义阴影滑条/任意半径，不能用它偷换完整需求。
非常小的图片单次删除，直接像素复制可能比区段模型更简单/快；统一推荐以长图多次编辑需求为准。
自定义视觉 B 路线必须先过原型门禁；多固定图或严格抗锯齿需求下，DComp 可能是更优折中。

## 3. 明确默认行为与用户范围

- 中段删除支持水平切线（删除整行）及垂直切线（删除整列），不做任意矩形挖空/AI 填补。
- 属于 Core 通用 Image Editor，不依赖 Scroll；OCR、普通截图、静态监控帧均可调用。
- “挂起监控”按当前 PiP 理解，只隐藏 PiP 不改变源窗口。固定图不做源聚焦自动隐藏。
- 自动隐藏建议初始关闭，Settings 改持久默认；右键提供跟随全局/本窗启用/本窗禁用。
- 阴影/圆角独立可选，建议初始关闭保持已有外观；启用后默认阴影 macOS 风格、圆角 Win11 系统规则。
- 视觉每区块提供 Win11/macOS/自定义；自定义继承此前预设参数。
  macOS 是 Nskry 近似风格，不宣称 Apple 官方精确参数；系统圆角转自定义使用标出的参考值。
- 可选效果只作用于宿主外观，不烘焙入截图、复制图、OCR 输入或实时监控源。

这些默认开关是建议，不是用户已经确认的设置变更。后续可按用户选择调整，而不影响技术边界。

## 4. 现状发现与架构落点

现有源代码核对：

- `src/ui/long_image_crop_window.*`：Core 共享编辑器、单连续 crop 导出，尚无区段模型；Paint 后备缓冲逐次分配。
- `src/main.cpp::StartPiP`：当前单 PiP/单 CaptureSession，来源 HWND 不由 PipWindow 持有。
- `src/capture/capture_session.cpp`：每次取帧后处理；Stop 是终止式，不是可恢复 pause。
- `src/ui/pip_window.cpp::RenderFrame`：没有隐藏/最小化门禁，每帧 cache copy 和 Present。
- `src/ui/pin_window.cpp`、`pip_window.cpp`：无标题栏/自定义 hit-test，只设置 DWM 边框色；不应重新引入粗边框或最小宽度。
- `src/core/settings_manager.*` 和 `src/ui/settings/settings_window.*`：尚无本轮设置；现有 service 方式可扩展。

建议落点（新名字是规划，不是现存接口）：

- `core/image_edit_model.*`：纯区段映射、历史、尺寸验证，与 HWND/GPU 无关。
- Core 编辑 UI：显示/工具模式/导出复用；按需执行器做像素物化。
- `core/monitor_visibility_policy.*`：纯可见性状态决策；小 WinEvent 适配器和采集协调器。
- `ui/window_visual_style.*`：Pin/PiP 共用几何、DPI、缓存、显示同步；不复制两套 blur/圆角逻辑。
- UserSettings 添加版本兼容的监控/外观值；Settings 原生 checkbox/trackbar/数值输入。
  trackbar 需初始化对应 common-controls 类，布局可滚动/分组，不能挤坏 Plugins 现有布局。

main 只接线，UI 只持有服务/值，不让插件篡改宿主 HWND，不把纯逻辑塞入插件 DLL。
API 2 ABI、reserved 字段、插件按需加载、前置插件后续协议均保持不变。
未来插件贡献编辑工具/样式需要单独版本化接口，本轮不暗建跨 DLL 私有依赖。

## 5. 怎么定义“低配”和“高性能”

这里定义**测试档位**，不是仅靠 CPU 型号/GHz 判断整机性能：

| 档位 | 建议覆盖配置 | 测试目的 |
| --- | --- | --- |
| 低资源参考 | 2–4 个逻辑处理器可用、8 GiB RAM、集显、1080p，包含节能/电池模式 | 确认没有周期忙等、整帧读回、无限历史；交互仍可用 |
| 主流参考 | 8–12 个逻辑处理器、16 GiB、集显或入门显卡、1440p | 常用体验与多窗口 |
| 高吞吐参考 | 至少 16 个逻辑处理器、32 GiB、4K，记录实际 GPU/内存带宽 | 压力上限，不是功能最低门槛 |

逻辑核数量不是性能充分条件，混合架构、温度、电源、GPU/RDP 都会改变结果。
同场景报告模型/OS/分辨率/DPI/内存/电源、固定图数量及源画面刷新率；
另记录一次同尺寸复制耗时和监控基线开销，才能判断资源峰值是否与机器能力匹配。
本轮不引入要求独显、AVX2 或 WebView 的新依赖；已有第三方依赖要求另行核对。

## 6. 测量方法：分开稳态和峰值

每方案用 Release，开/关同功能 A/B；相同机器、相同源画面，暖机后至少重复 10 次任务。
静态 idle 与动态监控分开，各记录 60 秒；不能用 60fps 采集场景宣称整个软件 CPU 理应接近零。

记录：主进程 Private Bytes/工作集/峰值、GPU 共享/专用内存、CPU 累计时间（注明单核或全机归一化）、
GPU engine/DWM 增量、唤醒/定时器次数、GDI/USER 句柄、帧处理/Present 次数，操作 p50/p95/max。
不得只把成本转给 DWM/worker 就宣称省资源；不能把 working set 降低当内存已完全释放。

场景：

1. 无 PiP/无编辑器/效果关闭：新增模块不创建 hook/timer/shadow HWND/图形表面。
2. 普通图 600×400；长图 2000×20000，水平/垂直/交叉切除 20 次及撤销，再复制/PNG/ROI OCR。
3. 一路 PiP 1080p 静态/滚动/动态 30 或 60fps，前台源/其它应用各停留 30 秒，快速 Alt-Tab 50 次。
4. 1/10/30 张固定图，分别移动/缩放/静止/最小化，100/150/200% DPI 和跨屏。
5. 开关效果、关闭重开 50 次后检查资源不随次数增长；历史/阴影缓存各有字节上限。

建议门禁（待真实低配测量确认，不是现有达标承诺）：

- 空闲新增功能不主动轮询；不会因监控每帧生成阴影或修改窗口 region。
- 切线/平移交互 p95 尽量低于 33 ms；复制/提交峰值按图像大小报告，不承诺任意长图 1–2 秒。
- 稳定隐藏后无自有 GPU crop/缓存复制/Present，回收会话后无采集 FrameArrived；统计允许切换时在途帧。
- 恢复新帧 p95 目标低于 250 ms；不达标再调整隐藏回收延迟/策略，不能假装旧帧就是实时。
- 关闭后释放自己持有的位图/纹理/窗口/hook；平台缓存未立即收缩要单独解释，不通过反复 GC/清 working set 美化数字。

## 7. 实施顺序与停点

1. Core 区段映射纯逻辑及测试 → 编辑工具/导出 → 普通图/固定图/PiP 静态帧入口。
2. 可见性纯状态机 → WinEvent 与全局/本窗开关 → 软暂停 → 稳定隐藏回收和恢复测试。
3. 视觉参数/预设/DPI 纯逻辑 → 原生圆角探测与小阴影原型 → 测 B 对 C 的资源/输入/z-order。
4. 通过门禁才接入完整 Settings/Pin/PiP；失败保持现有显示并提示降级，不引入粗边框。
5. 每阶段完整构建、现有 tests、新纯逻辑 tests、UI 验证、资源报告；每阶段能运行，不一次性重写 UI。

第一优先是功能正确、坐标/恢复不出错；第二优先是无持续无用工作；第三才是短任务峰值和视觉质量。
没有足够测量时不承诺某方案必然最省，本轮推荐作为原型起点而非不可修改的结论。

本轮仅新增 Proposal 文档，未运行构建/测试来冒充功能已实现，也未修改生效许可、提交或推送。
