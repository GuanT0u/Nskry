# GPLv3 发行合规、官方身份与防冒充规划

日期：2026-10-08。规划文件，不声称商标已注册、签名基础设施已上线或本次完成法律审核。
不修改 GPL-3.0-or-later，也不附加“禁止商用/禁止转售”的代码许可条件。

## 1. 先区分行为

| 情况 | 项目策略 |
| --- | --- |
| 合规地 fork 后销售、收费分发、提供安装/支持服务 | 明确允许；保留 Nskry 来源和适用版权/许可声明，清楚区分软件与服务，不冒充官方 |
| 分发 GPL 二进制却不履行源码/许可义务 | 收集证据、要求整改；核对发行方式与对应源码义务后处理 GPL 违规 |
| 冒充作者/官方认证、伪造签名、误导品牌关联 | 身份/商标/不正当竞争路径，按具体地区法律及平台规则处理 |
| 偷换恶意代码、模型包或更新链接 | 签名、hash、来源比对与安全公告，不能仅凭相同名称识别正版 |
| 分支改名、遵守 GPL 并清晰说明来源与改动 | 正常 fork；不把修改版一概认定为侵权或限制它运行 |

GNU 官方明确允许收费分发；GPL 第 7 节涉及商标权不授予等额外条款的边界，
它不是允许随意加“不可卖”的依据。GPL 复制/源码/再许可义务按第 4–6 节及实际交付方式核对。
历史 MIT 版本已经授予的权利不能因后续改用 GPL 被追溯收回；版权贡献与改许可权限应做台账。

## 2. 当前必须做好

1. 根目录完整 COPYING + 许可声明；核心安装包与自有官方插件包带许可证，保留全部第三方声明。
2. 每个发布版本关联精确源代码快照、构建脚本、静态依赖与可获取的对应源码；
   单独指向“最新版 GitHub”或仅附许可证不一定履行对应源码交付义务。
3. 来源页面清楚写“官方提供免费软件；收费服务/第三方分发不代表官方认可”。
   这属于事实提示，不撤销收件人的 GPL 权利。
4. 禁止虚假的 Official verified 标签。目前本地 source 类型与真正认证区分显示。
5. 逐版本核对模型权重许可、依赖再分发条件、源码来源，尤其本次 OCR 精确权重授权链尚待发布审核。

本轮加入完整 GPL 文本和打包配置，但未发布任何二进制，也未声称已完成所有源码/权重合规审核。
完整 GPLv3 文本随仓库 COPYING 提供；发行物必须保留许可内容。

## 3. 官方网站 / 插件目录上线阶段

- 唯一官方浏览入口、catalog URL、免费获取说明、发行历史、源码链接、第三方声明和举报入口。
- 维护者批准的发布者清单：ID、认证主体、维护责任、撤销状态；收编插件不得仅改 author 字段。
- 用独立的构建/发行密钥签名发布记录：plugin ID/version/API/compatibility/package URL/SHA-256/publisher。
- HTTPS 保护传输，包 hash 检测内容一致性；都不替代数字签名或真实发布者审查。
- catalog detached signature 精确校验签名载荷，拒绝歧义编码/无效签名；信任根与轮换流程在客户端明确版本化。
- 已认证官方版本校验失败时不静默当成第三方下载。用户仍可明确选择本地未验证包，但不得显示已认证标记。
- Authenticode 核心/可签 DLL 签名、发布 hash 和可复现构建证据是补充，不把 SmartScreen 或签名当绝对安全保证。
- “官方签名不可伪造”只证明签名来源；修改 GPL 代码仍合法，品牌关联需单独核定。

保留离线使用、本地插件安装和可修改源码，不加帐号激活、强制联网、DRM、远程 kill switch，
不通过签名体系剥夺 GPL 的修改/分发权利；适用 GPL 的安装信息义务另行核对。

## 4. 品牌与投诉流程

品牌使用政策草案：可真实描述“基于 Nskry”并保留合法归属信息；
未经项目方明确授权，不可声称自己是官方、获得官方认证/支持，也不可伪造认证图形。
该政策不限制代码许可授予的复制、修改和分发权，也不暗示尚未登记的权利已经成立。
品牌、图标著作权归属/商标登记及不同法域保护范围需先核对，必要时专业法律审核。

投诉需区分代码许可违规与冒充/诈骗；保留 URL、日期、下载包 hash、宣传截图、交易证据，
核实后先联系发布者/平台，必要时由权利人按实际法律途径处理，不公开敏感用户数据。
合法售卖支持服务不纳入滥用举报，不能承诺“加 GPL 就能禁止所有收费卖家”。

## 5. 发布门禁与顺序

P0：许可证/对应源码/依赖台账 → P1：官网与免费渠道、认证/签名/撤销 →
P2：品牌政策法务复核、透明投诉 → P3：复现构建、跨平台扩展。
不得先上线“官方已验证”徽标再补验证；不改 LGPL/GPL 等第三方代码的原许可。
同进程原生插件可能构成 GPL 组合程序；2026-10-11 起，明确附带
PLUGIN_EXCEPTION 的 Core/公开 SDK 提供限定的独立开源插件例外。
实际耦合仍须核对，不因属于第三方或 worker 进程就自动豁免复制实现和第三方依赖义务。

## 6. 2026-10-10 补充：来源与插件许可选择

允许第三方 fork 后销售、也允许收费安装服务，不把这两类合法行为列为“盗版”。
对外发行/服务说明应明确基于 Nskry，指向原项目的真实仓库/来源，保留适用的版权和许可声明；
fork 应说明修改者与改动，收费安装应区分官方免费软件和第三方服务费，不暗示官方授权。
不额外要求运行时强制水印、广告、不可删除的品牌按钮，不把这项说明变成限制 GPL 权利的附加条款。

第三方插件许可由开发者自行选择，项目不统一指定；这需要在原生插件组合边界上落实
限定的 GPL 插件链接例外，而不是只写“第三方不受影响”。

[正式例外 1.0](../../PLUGIN_EXCEPTION) 并同步 LICENSE/SDK/发行物打包；COPYING 原文不改。
只覆盖独立开源插件，闭源不在本次授权范围。授权记录与边界见
[说明](plugin_license_exception.md)。公开发行前建议专业法律复核；不能声称已经获得律师审查。
